Full snapshots here mean caller-supplied state metadata and hashes, not copied model weights. Repeated records retain compact digests and observed changed-parameter versions. Callers must not serialize weights, activations or whole caches into opaque result fields.

After process loss

Journal.recover(path) can inspect a journal and commit an already durable prepared record without running the measurement again. An intent without a prepared witness is uncertain. It cannot be retried, skipped or completed automatically.

A recovered writer cannot supply a fresh replica's observations as the old process's state. It may close the journal as incomplete with explicit unavailable observations. A new inference run still needs its own prospective protocol, native-history lineage, state guards and resource checks. This helper supplies none of those approvals or scientific controls.

Validation and preserved defect

The original implementation passes eleven new host tests and forty-two refusal cases. They include process exit before and after preparation, rollback of an uncommitted SQLite transaction, writer locking, content tamper, missing events and resource-stop evidence.

A later new regression shows that its final check accepts boolean and integer values as equal under Python dictionary equality. That failed case and historical version 1 remain preserved. Version 2 changes only the final guard: strict counter types, state structure and canonical state identity. Two new literal completion checks and ten targeted final refusals pass. The original eleven-test matrix is not repeated. These are software checks, with zero model, tokenizer, scorer, backward or optimizer calls.

Evidence and storage limits

The journal persists what the callbacks return. It cannot establish that a caller observed a genuine model, that a supplied hash describes all parameters, or that an intervention helps a task. Hash linkage detects the checked content changes; it is not an authenticity mechanism against a hostile editor who can rewrite the database.

SQLite transactions use rollback journal mode and FULL synchronous settings. The host tests exercise process exit and transaction rollback, not physical power failure or every filesystem. Atomicity depends on SQLite's operating-system and storage assumptions. See SQLite's atomic-commit documentation and Python's transaction documentation.

N43 remains resource incomplete. This new tool does not restore its missing final snapshots, certify its partial effects, change its frozen auditor or regenerate any completed measurement.
